# UI, keyboard behaviour and meaningful configuration

## U-01 Visual contract

Preserve the approved concept's thin terminal borders, aligned values, restrained mint accent, neutral readable text and quiet practice screen. Use normal terminal cells throughout; no dependency on image protocols, Nerd Fonts, ligatures, mouse or special fonts. Truecolor is an enhancement; support a readable 16-colour/terminal-default fallback. Pair colour with underline, cursor shape or labels for errors and selection.

Four primary destinations: Today, Train, Numpad, Progress. Settings/help are overlays, not permanent competing panels. Today shows the next guided session and short reasons for chosen work; Progress shows comparable trends and uncertainty. Avoid a dashboard filled with meaningless composite scores. Put only pace, accuracy, corrections, active time and relevant history where they answer a user question.

The browser mock-up's duplicate target/input fields are an interaction convenience. In the real TUI, default to one inline target region: correct typed units, wrong typed units shown with the expected target available, next-position cursor, and upcoming text. An optional separate-input mode may be implemented later but is not required. Keep stable word wrapping during an exercise; terminal resizing reflows predictably and is recorded. Never redraw a new random target because the terminal resized.

## U-02 Layout and resize

Reference viewport 100×32 cells; wide view at 120×40; minimum full experience 60×18. At narrower sizes remove side analysis and place numeric guidance below the prompt. Below the minimum show a minimal “terminal too small” screen and pause an active exercise; retain input/history and restore after resize. The renderer must be total for every nonzero bounded viewport, including 1×1, without panic or out-of-bounds access. Tests at the minimum and one cell below each breakpoint are required.

Themes: `cadence-dark`, `cadence-light`, `terminal`. Optional user theme file has named roles: background, panel, text, muted, border, focus, correct, error, error-background, warning, selected-background. Validate the full palette before publication; invalid theme retains the previous palette and reports one actionable diagnostic. Colours live in the theme adapter, not scattered widget literals. Accessible high-contrast terminal-default mode must remain usable with colours disabled.

The keyboard guide is optional (`auto`, `always`, `off`). In `auto`, show it for initial numeric exercises and hide when familiarity is established or explicitly dismissed. Highlighting means “expected next key,” not evidence of which finger/key the user pressed. Do not require physical keypad reporting for a numpad exercise to work. Capability status belongs in setup/diagnostics and a subtle relevant hint.

## U-03 Key ownership

In menus, arrows/Tab/Enter navigate; `q` quits and `?` opens help only outside text entry. During practice, all printable characters including `q`, `?`, `:`, `/` and digits are training input. Esc pauses and opens practice controls; another Esc resumes if safe. Ctrl-C follows a documented quit/flush path; it must not be a printable training character. Function-key navigation must pause before leaving active practice. Do not steal Tab/Enter from a code exercise where explicitly expected; command dispatch depends on the active input owner.

Backspace deletes one logical training unit; the physical Q6 remap is simply another Backspace event. A delete-word binding, if present, is one explicit action with a counted deletion range; it does not erase first outcomes. No invisible autocorrection. A paste is one classified paste event, never a simulated typed sequence.

Bindings are described once in typed command metadata used for dispatch, help, footer hints and headless action validation. Unknown/unavailable bindings must not appear as working shortcuts. Default mouse support can select buttons/settings, but every action is keyboard accessible.

## U-04 Settings

User-facing settings are limited to choices with a meaningful effect:

- Duration (5/10/15/20/30 minutes), enabled tracks and relative track emphasis.
- Active keyboard layout; numpad availability and decimal separator.
- Accuracy target within validated bounds; live pace on/off; strict correction versus flow assessment where supported. Strict correction is the default practice mode.
- Word frequency breadth, punctuation/capitalization level, explicit content packs, Rust/shell optionality.
- Theme, optional key guide, high-contrast mode and animation off/on (off by default).
- Explicit import/export/backup paths and opt-in content trace recording.

Do not expose every statistical coefficient or queue limit as a casual UI slider. Those belong in versioned trainer/runtime policies and diagnostics. A settings page can show effective values and provenance. All values are typed/validated; unknown keys or invalid values report the location and expected range. Partial configuration applies defaults to omitted fields, never to invalid supplied values.

Precedence: built-in defaults → explicit user config → CLI overrides. Relative XDG environment variables are ignored as invalid according to the XDG specification. Profile-dir overrides make test/headless isolation easy. Document layout/content compatibility; changing a score-affecting setting takes effect next exercise/session as specified, never halfway through a target. Theme/display changes can apply immediately through the reducer and do not reset learning.

In-app settings write config atomically through the data worker, with source version/digest checks to avoid clobbering an externally edited file. Preserve comments if using a TOML editing library. A write acknowledgement is required before the UI says “saved.” External changes load/validate off-thread and arrive through the same bus. A manual Reload Settings action is sufficient for v1; no need for a filesystem watcher.

## U-05 Results and explanations

After a block: one concise observation, one next action and relevant numbers. Example: “`str` had 3 errors in 22 first attempts; we will revisit it in different words.” Never claim certainty from two trials. After the daily plan: accuracy and correctly completed throughput per track, review outcome, and transfer probe when applicable. No live speed target that punishes every hesitation. Keep the user in practice with minimal navigation.
